# 0.2.0-preview.4 release

Published on NuGet from source commit
`0a523826c2d7281164ee0b1826fcb1bbee2d6689` after remote CI on Windows and
Ubuntu and user-run publication. This release adds the AE-6.2 durable
authority-subject binding on top of [0.2.0-preview.3](0.2.0-preview.3.md).

## Durable authority-subject binding (AE-6.2)

- `WorkflowRun.AuthoritySubjectBinding` is an opaque, host-owned identity
  that records whose current authority governs a run's protected runtime
  effects. Zhinu never interprets it. It is set once when the run is
  admitted, is never updated afterward, and propagates to forked runs. A
  null binding means the run carries no authority identity: requesting an
  authorized runtime effect for such a run fails closed. It is identity
  only, never a permission grant and never a stored authorization decision.
- `StartAsync`, `StartHandleAsync` and `RunAsync` on `WorkflowEngine` and the
  focused starter/runtime interfaces accept an optional
  `authoritySubjectBinding` value. The exact resulting signatures are
  recorded in the shipped/unshipped public API baselines.
- SQLite schema 7 persists the binding on the run row through an additive
  6-to-7 migration, extending the existing 5-to-6 chain.

## Compatibility

Back up the database and stop older workers before opening it with this
package. Schema-6 binaries reject a schema-7 database; downgrading requires
restoring the backup. The start-signature change replaces the previously
shipped overloads with versions taking the additional optional parameter, so
binaries compiled against the earlier overloads must be recompiled. The
authorization behavior of existing unprotected runs is unchanged; the
binding is recorded identity only.

Qualification evidence for the authorization phase is in
[the qualification record](../qualification/workflow-authorization.md);
`AuthoritySubjectBindingTests` covers binding persistence, fork propagation
and fail-closed use.
