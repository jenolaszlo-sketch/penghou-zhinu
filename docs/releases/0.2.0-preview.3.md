# 0.2.0-preview.3 candidate

This candidate adds the three Marang M5 execution-evidence read primitives on
top of preview.2, plus operator CLI inspection commands. It follows the
[public API policy](../public-api-policy.md): all public API changes are
additive; existing runs, store contracts, and compiled consumers retain their
behavior.

## M5 execution-evidence reads

- **Durable vs advisory event classification.** New `WorkflowEventDurability`
  (`Durable`/`Advisory`), `WorkflowEventTypes.Durability(eventType)`, and a
  computed `WorkflowEvent.Durability` property. Committed execution transitions
  classify as durable; `progress` classifies as advisory; application-defined
  types default to durable. No schema, persistence, ordering, or cursor/export
  change.
- **Bounded cursor-based event pages.** New `WorkflowEventPage`
  (`Events`, `NextCursor`, `HasMore`, `ThroughDurableSequence`,
  `RetentionFloor`, `ResyncRequired`) with `IWorkflowEventPageReader`
  (engine) and `IWorkflowEventPageRepository` (store). Cursor is the last
  consumed sequence (`Sequence > cursor`, strictly exclusive); `hasMore` is
  explicit; `throughDurableSequence` never advances on advisory events and never
  regresses across pages. Stateless and independent of durable export
  acknowledgement. No schema change.
- **Atomic run snapshot with durable watermark.** New `WorkflowRunSnapshot`
  (run, current-revision steps, dependency edges, waits, artifacts, bounded
  external operations, active operation, generation + instance + dispositions,
  source run/lineage, recursive child snapshots, derived diagnosis) with
  `ThroughDurableSequence`, plus `RunSnapshotOptions`,
  `IWorkflowSnapshotReader` (engine), and `IWorkflowSnapshotRepository`
  (store). All rows and the watermark come from one deferred read transaction
  on one connection, rolled back without writing. No schema change; no new
  identities.

See [observability](../observability.md) for the event-page and run-snapshot
contracts, and [semantics](../semantics.md) for the durability classification.
`GetRunProgressAsync` is unchanged. A consumer protocol of snapshot at
watermark D plus event pages after D is documented; Generation/operation
transitions remain snapshot/state-only by product decision (no stream events).

## Operator CLI inspection

- `runs external-ops` (read-only external-operation handles), `runs cancel`
  (audited remediation), `runs restart` (idempotent receipt remediation),
  `runs wait` (terminal-state wait), `runs evidence` (correlated diagnostic
  view), `runs graph` (read-only run graph), `runs list` workflow/version and
  ISO 8601 created-after/before filters, and run lineage/deadline in
  `runs show`. See [operator walkthrough](../operator-cli.md).

## Proofs and hardening

- Cross-process child trace continuity proof (parent/child share the durable
  trace ID across a process boundary; run and step identities stay distinct).
- Windows test-cleanup hardening (engine disposal before directory cleanup;
  resilient temp-directory removal).

## Compatibility

SQLite schema is unchanged from preview.2 (still version 6); no migration is
needed. Public API additions only; package validation runs against the
preview.2 baseline. Existing unenforced runs, compiled consumers, and the
isolated package-closure and legacy-binary probes are qualified separately.

This file records a local release candidate, not a published package.
Publication remains the user's NuGet CI step after qualification and review.
Marang M5 adoption follows publication of the qualified release.
