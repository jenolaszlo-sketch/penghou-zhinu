# Q33: explicit branch replacement and retirement

Qualification in progress; final source, test and package receipts are recorded
in `q33.json` when the checkpoint is sealed. This record extends the native
profile after [ZG-7](zg7.md); it does not modify its original sources or archives.

## Contract and implementation

The [selection/retirement contract](../../activity-groups-branch-replacement.md)
adds explicit `ReplacesFanOutKey` admission through a repository advertising
`IWorkflowGroupFanOutReplacementRepository`. The existing keyed fan-out coordinate
represents a selected branch, including a body with independently durable nested
operations. A replacement requires a fresh scope, the same group root and parent,
and a newer completed revision of the same controlling step.

Admission atomically installs the new immutable enumeration, appends a retirement
receipt and durable event, cancels current unfinished old members and their active
waits, and clears their leases. Completed results, prior revisions, memberships,
occurrences and closure proofs remain unchanged. Unmaterialized selected items
are retired by the expansion receipt. Missing or corrupt receipts fail closed.
Concurrent replacements have one winner; losing admission rolls back all rows.

Retired scopes cannot admit, claim or complete work. Retired members cannot be
restarted, and dependent restart excludes them. Current ancestor state excludes
retired descendants; historical inspection and frozen snapshots retain evidence.
Omission without explicit retirement continues to prevent run completion.

The occurrence model, hash and coordinate encoding are unchanged. Native package
version advances to `0.2.0-preview.10`. Additive schema **10** introduces the
retirement table so older workers cannot ignore changed completion obligations.
Supported prior schemas migrate transactionally; schema-9 migration is exercised
with actual selected work before replacement.

## Proof boundaries

The first regression failed because the replacement branch ran but the original
unfinished enumeration still prevented completion. Its red TRX is retained.
Review also reproduced a direct-store bypass: an ordinary new step could join a
retired simple-item occurrence without a typed fan-out claim. The additional
membership-chain fence rejects it before inserting a step or membership; both
empty/nonempty replacement red cases and their corrected results are retained.
Four separate process-loss cases kill a worker after the new selection commits,
inside retirement/cancellation before transaction commit, after admission before
dispatch, and during partial replacement work. A fresh worker uses a deliberately
different selector; it reuses the historical decision and preserves completed
effects, step IDs, occurrence IDs and parentage. Transaction loss leaves neither
retirement nor a replacement enumeration; post-commit loss retains both.

Additional cases cover completed old closures, A → B → A using a fresh scope,
empty replacement, unfinished unmaterialized items, competing admission, stale
lease rejection, retired claims/restart, missing/self replacement, missing receipt,
unsupported providers, retention cascade, and fork rejection before destination
creation. Public package probes independently exercise replacement/query behavior
and the unchanged preview.9 worker's schema-10 rejection with unchanged database
bytes. Existing package closure and public legacy-binary probes remain separate.

## Limits

This qualifies explicit native branch selection through the supported durable
mechanism. Arbitrary C# conditionals do not implicitly retire work. Fuwen evolving
selection lowering and a new Fuwen package pin are deferred. The previous Fuwen
preview.18/native preview.9 package closure remains frozen. Forking a run with
retirement receipts is rejected until separately qualified. No external effect is
undone by retirement, and no package publication or merge is implied.
